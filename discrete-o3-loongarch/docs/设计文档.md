# 离散式乱序三发射架构设计

> 面向对象：`T2026143250012561/src/vivado_cannot` 当前 NOP 核（SpinalHDL 1.8.1）。
> 目标：200MHz（Artix-7 200T，-2 级，5.0ns 周期），乱序三发射，每个寄存器间路径
> **逻辑级数 ≤10（目标 ≤7）**，消除高扇出 LUT 网，**不设中心式决策环**。
> 配套骨架代码：`src/vivado_cannot/src/pipeline/discrete/`（RippleSelect / SystolicIssueQueue / RegisteredCommit）。

---

## 0. 结论先行：能不能？

**能，而且是当前网表数据指向的唯一出路。** 三条定量依据：

1. 最新 perf 布线（8/17，WNS **-3.810ns**）：头号路径 15 级，逻辑仅占 25.4%，
   **布线占 74.6%**；cpu_clk 域 **58.4% 端点**违例。逻辑级数只是诱因，跨 die 长线
   + 大扇出才是大头。
2. round-2~4 实测：每压缩 1 级逻辑只省 ~0.1ns，而 **88/100 条最坏路径出自 ROB
   popPtr 一个扇出锥**（popPtr→RAM→popCount→90bit payload→5 个模块同拍广播）。
3. 按你引用的宝典经验值（LUT+走线 0.5ns/级）：5ns 周期最多承载 10 级；现有网表
   峰值 12~15 级，逐点压缩永远追不平，只能**结构性打散**。

"离散式"的含义与实现方式，一句话概括：

> **把每一条"环"（wakeup 环、commit 环、redirect 环）在环上至少切断一次、插一个
> 寄存器；把每一个高扇出锥从 LUT 驱动改成 FF 驱动；把每一条跨模块组合链在模块
> 边界换成寄存器消息。** 切完之后，整个数据通路变成一条"无数级小逻辑前后咬合"
> 的流水链条（systolic pipeline），控制信号全部本地化，只剩寄存器间 ≤7 级的局部
> 小函数。

要付的代价（全部已验证过"正确性由恢复机制兜底"）：

| 代价 | 大小 | 补偿 |
|---|---|---|
| 提交动作整体晚 1 拍（CM2） | IPC ≈ -1~2% | 删掉 fwdCands 锥（~2k LUT）与 popPtr 锥 |
| 广播寄存化（宪法代价）+ 保留 RRD | 依赖链 4→5 拍（IPC ≈ -2~4%） | 读进胞元买回 1 拍 → 4 拍持平；组合 tag 豁免 → 3 拍（§4.2 末段） |
| 脉动 2 拍选择（可选） | 依赖链再 +1 拍 | 仅在布线需要时启用 |
| 误预测恢复晚 1 拍 + 前端拉长 ~2 拍 | 误预测罚 +2~4 拍 → IPC ≈ -3~-12%（依预测器质量） | EXE 提前重定向可收回 2~3 拍（§4.3） |
| 少量重复寄存器复制 | FF +10~15k | 200T 有 534k FF（每 SLICE 16 FF > 8 LUT），绰绰有余 |

**同频口径合计：IPC ≈ -5~-15%**。频率口径：现状最坏路径 8.81ns（200MHz 下
WNS -3.81）→ 当前设计实际可收敛频率约 110~130MHz；离散化目标 200MHz = 频率
+55~80%，净收益 ≈ **+25~+65%**（§7）。结论：即使 IPC 损失取最坏值，仍显著正收益，
但"每阶段实测 IPC、损失超限即上补偿手段"是执行纪律。

必须坦白的边界（§6）：**PRF、TLB、ROB RAM、Cache 这些"数据存储"不可能也不应该
分布式**——CAM 比较本身已是逐项本地比较；要消灭的是"决策环"与"扇出锥"，不是
集中存储。"集中存储 + 寄存器界定的本地决策"正是本方案与纯中心式设计的分界线。

## 1. 现状：两条中心式决策环 + 三类扇出锥

当前核心结构（代码位置见括注）：

```
取指 IF1→IF2→IF3 | 译码 ID→ID2 | RENAME | DISPATCH
INT×3: ISS→RRD→EXE→WB   MULDIV: ISS→RRD→EXE→WB
MEM: ISS→RRD→MEMADDR→MEM1→MEM2→WB→WB2
提交: robState(4bank×8) 投机读 popPtr+0..5 → fwdCands 同拍前递折叠
      → popCount 选择 → 90bit payload → ARF/PRF/freeList/BTB/TLB/CSR/redirect 同拍广播
```

### 1.1 环 A：提交决策环（`ROBFIFOPlugin` + `CommitPlugin`）

```
robState Q → 投机读(popPtr+0..5, 3级) → fwdCands 折叠(派发+WB 前递, 4级 mux)
→ complete/except/mispredict(2~3级) → fire → popCount(2级) → payload pick(2级)
→ 同拍做全部提交动作(ARF/PRF/freeList/BTB/TLB/CSR/redirect)
```

- 12~15 级、横跨 die（X45→X129），popPtr[0] fo=87，中间网 fo=155/114/248。
- fwdCands 存在的唯一原因：**同拍前递**（WB 同拍写 robState、派发同拍写 robState）。
- 若 WB/派发写入与读出之间插一个寄存器，前递锥整体消失。

### 1.2 环 B：唤醒环（`CompressedQueue.genGlobalWakeup`）

```
WB clearBusy(PRF busy 位写) → DISPATCH 拍组合比较(6 广播口 × 8 槽 × 2 源 OR 树, 3~4级)
→ queue.rRegs.valid 寄存器 → 下一拍 ISS 选择
```

- 唤醒本身已"半离散"（ready 位是寄存器），但比较发生在 **DISPATCH 拍**，与入队/
  压缩/读 busy 同拍混排；且曾有 TLB 快照→IQ valid 的 15 级跨模块链。
- 离散化 = 把"比较→置位"收敛成**每个胞元一个单写者**的局部逻辑，广播源必须是 FF。

### 1.3 三类高扇出锥（按实测报告）

| 锥 | 组成 | 修复原则 |
|---|---|---|
| ROB popPtr 锥（88/100 路径） | popPtr→RAM→popCount→payload→5 模块 | payload 寄存 + popPtr 只驱动读地址 |
| commit 广播链 | commit(except)→regFlush→ICache refetch→IF1 stall→regPC.CE | redirect 全链消息化（§4.3） |
| 复位恢复网 | LUT 驱动 6956 端点异步复位（-2.708ns 单独一项） | 复位网拆分（§5.3） |

## 2. 离散化判据（本设计的"宪法"）

1. **级数宪法**：任何 FF→FF 路径逻辑 ≤10 级，目标 ≤7 级；级数不达标即否决该切法。
2. **环切割宪法**：组合逻辑环（wakeup/commit/redirect）上每条边必须至少经过一个
   寄存器；违反即形成新的中心式环。
3. **单写者宪法**：每个状态位只允许一个胞元写入（wakeup 位归 IQ 胞元、robState
   位归 ROB、busy 位归 PRF）；杜绝"两个模块组合链合写一个位"。
4. **扇出宪法**：LUT 驱动网 fo≤8；FF 驱动网 fo≤128（超则复制 FF）；所有 RAM/CAM
   地址端口由 FF 驱动；跨模块网一律 FF 驱动。
5. **边界宪法**：模块边界 = 寄存器（payload 寄存一拍再分发）；每个消费者模块只
   接收自己需要的字段的寄存副本（字段级裁剪）。

## 3. 总体切片图：一条 17 级的"咬合链条"

```
IF1(PC mux+BTB地址) → IF2(BTB/PHT/RAS读+命中) → IF3(目标选择+redirect接收)
→ ID1(缓冲pop) → ID2(65路匹配+字段mux) → ID3(epilogue)     [§4.6: 3 拍化]
→ RN1(RAT读+组内RAW) → RN2(空闲表读+写口装配)      [RN2 可选合并]
→ DISP(派发仲裁3×3)
→ IQW(唤醒胞元:tag比较+置位;data捕获晚1拍) → IQS(选择+载荷mux)  [IQS 可并入 ISS]
→ ISS(发射握手) → EXE(ALU/BRU) → WB→写引擎(仲裁+PRF写+busy清+双总线发射)  [RRD 取消:读进胞元]
→ CM1(提交决策+payload寄存) → CM2(全部退役动作)
```

- 每个箭头 = 寄存器；每拍逻辑见 §5.1 预算表。
- 三条"消息总线"（全部 FF 驱动）：
  - **唤醒广播（双总线）**：tag 总线（6bit，置 ready）+ data 总线（tag+32bit，晚
    1 拍捕获数据）——均 FF 驱动，胞元本地比较（§4.2/§4.6）；
  - **重定向消息**：CM2/WB → IF1/IF2/ID/DISP/IQ 各模块的寄存副本（§4.3）；
  - **提交邮箱**：CM1 寄存器 → CM2 各消费者按字段取用（§4.1）。

与现状的差异只在四处结构：提交（§4.1）、发射（§4.2）、重定向（§4.3）、读/写
分离（§4.5/§4.6）。其余（3 级取指、MEM 7 级切片、banked PRF 读树）**全部保留**。

## 4. 三大离散结构

### 4.1 提交链：CM1/CM2 两拍 + 邮箱（最大杠杆，消 88 条最坏路径）

**改动（对照 `ROBFIFOPlugin.build`）：**

1. **删除 fwdCands 全部前递折叠**（~2k LUT）。理由：WB 写 robState 与派发写
   robState 都是同步写，读出在寄存器 Q 侧；"同拍前递"只为省 1 拍提交延迟，
   而它正是 90bit 锥的源头。删掉后，最老条目状态 = `readState(popPtr)`、
   `readState(popPtr+1)` 的直接寄存读（库内 8:1 ≈3 级 + 库间 4:1 ≈2 级，共
   4~5 级），**不再有 popCount→payload 的串行选择**。
2. **CM1 = 纯决策**：`c0/c1/blk/mp/uq/intPending/uncachedMask → ready0/ready1
   → fire → popCount`（≈5 级，全部输入是寄存器：robState Q、intPending 寄存器、
   uncached FSM 状态寄存器）。popCount 只做两件事：更新 `popPtr`（局部指针加法，
   fo≈8）、标记邮箱哪几条有效。
3. **payload 寄存一拍成"提交邮箱"**：
   `mailbox = RegNext(entry0, entry1, fire0, fire1, popCount, redirect信息)`。
   邮箱是 CM2 的**唯一输入**；ARF/PRF/freeList/BTB/TLB/CSR/ICache/StoreBuffer
   各自取字段寄存副本——90bit 大 mux 从关键域消失，每个消费者只看到自己需要的
   几个 bit。
4. **robInfo 的 RAM 读路径**（ReorderCacheRAMOutReg + fresh bypass + rsp 副本
   mux，≈4 级）整体落在 CM1→邮箱寄存器之间，级数归 CM1 预算。

**代价**：指令 WB(n) 最早 n+2 拍退役（原 n+1）；误预测重定向晚 1 拍。
**验证锚点**：perf 报告中最坏 15 级路径（popPtr→intResult）在本结构下变成
`robState Q →4~5级 mux → 决策5级` 或 `RAM读4级 → 邮箱寄存器`，两段均 ≤7 级。

**必须专项设计的对齐协议（最终 review 新增，正确性风险）**：现状 `needFlush` 与
`pop` 同拍（"flush 周期同时 pop"）；离散版 needFlush 从 CM2 出、比 popCount（CM1）
晚 1 拍——flush 到达时 popPtr 已前进。需在 Phase 1 明确：CM2 拍 flush 落在
ROB/freeList 上时，freeList 的 recover 技巧（`pushPtr := popPtr`，要求"recover
周期不动 push/pop"）与该拍 freeList 的邮箱 push 的先后关系；备选做法是 flush
直接清指针 + 该拍禁止 push（等价于现状语义，牺牲 1 拍）。uncached FSM 同理：
stateBoot 的判定条件（isUncachedUOP && complete && !hasExcept）改用邮箱前拍值，
确认不存在"已 pop 才发现应阻塞"的窗口。

**"无中心环"的证明**：提交环的边 = robState 读→决策→payload→下游→(回写 robState
指针)。现在 payload 处有邮箱寄存器、指针更新在 popPtr 寄存器、下游动作在 CM2，
环上任何一圈都至少跨 1 个 FF → 组合环不存在。

### 4.2 发射链：胞元化 IQ（前后咬合的脉动结构）

每个 IQ 槽 = 一个**胞元**，胞元间只有相邻连线（fo≤3）；胞元内部 5 个功能位面：

```
胞元 i 状态: valid | uop(载荷) | rTag[0..1] | rReady[0..1] | (可选 rData[0..1]) | wTag | robTag
```

1. **唤醒位面（单写者）**：`rReady_next(j) = rReady(j) || Σ_p (wbTag_p == rTag(j))`。
   广播来自 WB 输出寄存器（FF 驱动，fo≈80，MAX_FANOUT 复制 2 份）；每个胞元 1 级
   比较 + 1 级 OR 进 FF。**IQ 位不再被 TLB/执行级组合链驱动**——单写者宪法生效，
   round-4 的 "TLB snapshot→IQ rRegs valid" 15 级链从此不存在。
2. **乒乓唤醒（可选，对应宝典乒乓操作）**：rReady 双 bank（A/B），奇偶拍交替：
   偶数拍广播比较写入 bank B、选择读 bank A，奇数拍反之。比较+置位与选择各得整拍
   预算；当唤醒广播升级为"捕获式唤醒"（含 32bit 数据）时此模式必选。
3. **选择位面**：`req(i) = valid && rReady(0) && rReady(1)`，从 req 中按年龄序
   取 issueWidth 个 grant。两种实现（`RippleSelect.scala`）：
   - **树形**（默认）：前缀/优先树 3~4 级，1 拍完成选择，fanout 每 ready 位 ≤3；
   - **脉动链**：每胞元只与前胞元相连，1 个 LUT+1 个 carry/跳，8 槽 = 8 跳 ≈
     1.2~1.6ns 全局部走线——**这正是"无数级小逻辑前后咬合"的极致形态**，grant
     寄存一拍、载荷 mux 下一拍（2 拍选择）。
4. **载荷位面**：`payload(p) = MuxOH(grant(p), slots)`（3 级），或脉动式随链携带
   （每跳 2:1 mux，与 grant 同拍并行）。
5. **移位位面（出队压缩）**：被发射槽清空，后续槽向低位平移——沿用现有
   `CompressedQueue` 的 popCounts 前缀链（或 3 级树前缀），每槽 mux 输入仅来自
   ≤4 个相邻槽，**无长线**。

**依赖链核算**（back-to-back；广播按"模块边界=寄存器"宪法寄存一拍，比现状的
组合唤醒 +1 拍）：WB(n) → tag 总线(n+1) → 唤醒置位(ready 可见 n+2) → 选择/ISS
(n+2，树形) → RRD(n+3) → EXE(n+4) → WB(n+5)＝**5 拍（保留 RRD）**；
读进胞元后取消 RRD → WB(n+4)＝**4 拍（与现状持平）**；脉动 2 拍选择 → WB(n+5)
＝5 拍。

**捕获式唤醒（默认：读进胞元，买回宪法的 +1 拍）**：唤醒广播拆成**双总线**——
- **tag 总线**（n+1 拍，6bit）：胞元比较命中即置 rReady，唤醒关键拍只有轻量比较；
- **data 总线**（n+2 拍，tag+32bit）：胞元再比一次 tag（1 级）命中即捕获进
  rData——数据在 EXE 需要它的前一拍到达，**链长不变**（§4.6 判据 #1）。

发射时直接使用 rData，**跳过 RRD 的 PRF 读**。树选下链长 4 拍
（WB n → tag n+1 → ready n+2 → select n+2 → EXE n+3 → WB n+4），与现状持平；
重负载的 32bit 总线拿到整拍路由预算，6 个 PRF 读口移出关键环集中到派发侧。

**宪法豁免（最终 review 新增，可再省 1 拍）**：tag 总线是 6bit 轻量网、每队列
复制后 fo 可控，且现状 perf 报告 top-100 中并无 WB→IQ 比较网——按"默认规则 +
数据豁免"原则，**tag 总线可保留组合驱动**（现状风格），只强制 data 总线寄存。
则链长为 WB(n) → 组合比较(n) → ready(n+1) → 选择(n+1) → EXE(n+2) → WB(n+3)
＝**3 拍，比现状快 1 拍**。豁免条件写入 §9：该网若出现在 top-N 违例报告即收回
豁免、改回寄存。宪法 #4/#5 由此从"一律"改为"默认，违例数据可豁免/可收回"。

### 4.3 重定向消息链（拆断 round-4 top1 的跨模块链）

现状：`commit(except)→regFlush→ICache refetch→IF1 stall→regPC.CE` 一条组合链。
离散化后重定向是**三段寄存器消息**：

```
CM2/WB(检测) → [重定向寄存器: needFlush+target+PC] → IF1(下一拍取 PC mux 输入)
                                                  → ICache/BTB(各取地址字段寄存副本)
                                                  → ID/DISP/IQ(flush 位寄存副本)
```

- 每跳 1 拍、每网 fo≤3（按消费者复制 FF），**任何一拍都不存在"检测→取指"组合链**。
- BTB/PHT 更新、GHR 恢复走同一邮箱（晚 1 拍），恢复后 1~2 拍用旧 GHR，多一次
  误预测的代价，round-4 候选 #1 已论证可接受。
- 误预测罚（取指→首条有用指令执行）：离散链前端 14 级（IF×3+ID×3+RN×2+DISP+
  IQS+ISS+EXE+WB+CM1），提交侧重定向 ≈ **18 拍（现状 ~14，+4）**；**EXE 提前
  重定向为标配**（需"无更老异常"前缀位——由胞元链逐项寄存计算，2~3 拍隐藏在
  执行之后），罚 ≈ 15 拍（+1）。+4 拍 × 误预测率 1~3%/指令 ≈ -3~-8% IPC，
  故阶段 2 就必须落地提前重定向，而非可选。

### 4.4 前端/重命名/执行/存储：保留 + 补刀

- 取指 3 拍、译码 2 拍、MEM 7 拍切片、PRF 3 级读树、空闲表 MultiPortFIFOVecOutReg
  ——均已离散，**不动**。
- 重命名：RN1 做 RAT 读 + 组内 RAW 匹配（3×3 比较阵，2 级），RN2 做空闲表
  pop（移位队列头 3 槽读，本地）+ ROB/IQ 写口装配。空闲表本身就是"移位队列"——
  离散结构的现成例子。
- 发射队列"槽"改由 `SystolicIssueQueue` 提供（`pipeline/discrete/`），
  MULDIV/MEM 队列同构（深度 3/5，issueWidth=1）。

### 4.5 读/写分离：再分割的边界（"更细"到什么程度）

现状的三发射**并非**三个完整单发射克隆——IQ/PRF/ROB/空闲表已经共享，只有
ISS/RRD/EXE/WB 是每路一份。把"读"与"写"从每路流水里再拆出来的四种形态，
按收益排序（判据：每次更细的分割必须买到级数、扇出、链长三者之一，否则只是
加延迟——宝典警示：流水寄存器过多 → FF/控制集上升 → 布线拥塞）：

| 形态 | 做法 | 买到什么 | 代价 | 判定 |
|---|---|---|---|---|
| B. 读进胞元 | 操作数数据进胞元：派发时读 PRF 存 rDataInit；唤醒广播拆**双总线**（tag 总线置 ready、data 总线晚 1 拍捕数据）；发射后**无 RRD 级** | 依赖链 4 拍不变但唤醒关键拍只剩 6bit 比较；6 个读口移出关键环集中到派发侧 | 32bit 数据总线（FF 驱动+按 IQ 组复制，整拍路由预算） | **做，设为默认** |
| C. 写集中（广播合并） | 3×INT+MULDIV+MEM 的 WB 结果汇入写引擎，**只合并唤醒广播口**（5~6→2~3，暂存仅用于广播）；PRF 写口保留 5 个（写口 mux 仅 2 级，非瓶颈，砍它反而引入写口冲突延迟） | 广播口 5~6→2~3（胞元比较 OR 树 3 级→2 级、双总线扇出减半）；单点可再切拍 | 3:1 广播仲裁（2 级、寄存输入）+ 每路 1 项广播暂存，冲突时该路的唤醒晚 1 拍（概率低） | **做（阶段 3）** |
| A. 共享读级 | 三路的 RRD 合并成集中读级（6 口同址） | 读地址 mux 与 PRF 读树同域放置 | 无级数/扇出收益，只是搬家 | 不做，布线点名再说 |
| D. PRF 乒乓 | PRF 双 bank，写 shadow/读 active 交替 | 写口 mux 整拍预算 | +63×32×2 FF，写口本就 3 级 | 不做，应急预留 |

另有一处隐藏的读/写同拍耦合应一并切断：`PhysRegFilePlugin` 里 dispatch 读 busy
与 WB 清 busy 的**同拍旁路**（`readBusys.foreach { when(writeOH.orR) r._2 := False }`）。
离散版改为取消该旁路——派发看到旧 busy 只会把源标成"未就绪"，胞元随后被唤醒
广播修正，代价恰 1 拍，换来"busy 读路径无环"（单写者宪法彻底落地）。

### 4.6 第六轮 review：更细拆分的裁决表

判据同 §4.5：**每次更细的分割必须买到 {逻辑级数, 扇出, 依赖链长} 三者之一，
否则只买到延迟**（宝典：流水寄存器过多 → FF/控制集上升 → 布线拥塞）。本轮
新增与复核：

| # | 拆分 | 买到什么 | 代价 | 判定 |
|---|---|---|---|---|
| 1 | 唤醒广播拆**双总线**：tag 总线（6bit，置 ready）+ data 总线（tag+32bit，晚 1 拍捕数据） | 唤醒关键拍只剩轻量 6bit 比较；32bit 重总线拿到整拍路由预算；数据在 EXE 用前到达，链长不变 | 胞元对 data 总线再比一次 tag（1 级） | **做**（读进胞元的标准形态） |
| 2 | 译码 3 拍化：FB pop 独立成拍（ID1=pop，ID2=65 路匹配+字段 mux，ID3=epilogue） | 消 round-4 未修的 "FetchBuffer popPtr→PHT" 13 级路径 | 前端→派发 +1 拍 | **做**（数据支持） |
| 3 | INT 队列功能分体：3 口纯 ALU/CMP + 1 口 SYS 小队列（BRU/CSR/TIMER/INVTLB） | 主队列选择去掉每口 fuMatch 掩码；SYS 队列 4 项 1 口选择更小 | 峰值不变（现状 BRU 本就在 lane0）；多一份小队列逻辑 | 中期选项 |
| 4 | 提交动作按消费者二次分期（每消费者自取字段寄存副本） | 邮箱 fo≈8，各模块仅见所需字段 | 无 | 已含（§4.1） |
| 5 | PRF 读双拍化（地址寄存→数据寄存） | 读树 3 级本就达标，无收益 | 全指令 +1 拍 | 不做 |
| 6 | EXE 分拍（ALU 与 BRU 拆两拍） | 每拍各少 1~2 级 | 全指令 +1 拍换 1 级 | 不做，布线点名再说 |
| 7 | 载荷按字段分期交付（每级只带下一级需要的字段） | 每拍 payload 变窄、路由变短 | 属打包原则，非独立结构 | 并入 §2 判据 |
| 8 | 全级乒乓/双相流水 | — | 吞吐减半或面积翻倍 | 不做 |
| 9 | TLB 比较/命中分拍 | MEM1 深时救急 | +1 拍访存 | 保险（round-2 B1） |
| 10 | ROB 分体 4→8 bank | 级数持平（2+3 与 3+2 互换） | popPtr bank 选线扇出翻倍 | 不做 |
| 11 | DISP 分拍（claim+读地址 → 数据 mux+入队写） | 读进胞元后 DISP 含 6 口 PRF 读，分拍各得 ~3 级 | 派发 +1 拍 | 保险 |
| 12 | tag 总线两级扇出（中继寄存器 + MAX_FANOUT 复制） | fo 再降一档 | 唤醒 +1 拍（ready n+3） | 保险，仅在布线点名时 |

## 5. 预算表

### 5.1 每拍逻辑级数（FF→FF，目标 ≤7，上限 10）

| 拍 | 内容 | 级数 |
|---|---|---|
| IF1 | PC mux(3:1 重定向选择) + BTB/RAS 地址 | 2 |
| IF2 | BTB/PHT/RAS RAM 读(输出寄存) + 命中比较 | 3 |
| IF3 | 目标选择 + 重定向仲裁 | 2~3 |
| ID1 | FetchBuffer pop（§4.6 #2 独立成拍） | 2~3 |
| ID2 | 65 路匹配 MuxOH + 字段 mux | 3~4 |
| ID3 | epilogue/异常汇总裁剪 | 3 |
| RN1 | RAT 读 + 组内 RAW(3×3) | 3~4 |
| RN2 | 空闲表 pop + ROB/IQ 写口装配 | 3 |
| DISP | fuMatch 3×3 + push 仲裁（读进胞元时含 6 口 PRF 读） | 3~4 |
| IQW | tag 总线比较 + OR 置位；data 总线捕获(晚 1 拍) | 2 |
| IQS | 选择(树 3~4 / 脉动 8 跳) + MuxOH 载荷 | 4~8 |
| ISS | 发射握手 + 槽释放 | 2 |
| RRD | PRF 读树(3 级)——读进胞元后取消 | 3 |
| EXE | ALU/比较器/BRU(32b 加 = 8 列 CARRY 但同列延迟) | 4~5 |
| WB | 写引擎仲裁 + PRF 写 + busy 清 + ROB 写 + 双总线发射 | 3~4 |
| CM1 | 决策 5 级 / RAM 读+fresh 4 级(平行) | 5 |
| CM2 | ARF/PRF/freeList/BTB/TLB/CSR/redirect 各自动作 | 3~4 |

峰值 8 级只出现在脉动选择（全局部走线，fo≤2）；其余 ≤5。与宝典公式对照：
10 级上限 = 5.0ns/0.5ns，7 级目标给 FF C→Q + setup + 布线方差留 ~1.5ns。

### 5.2 高扇出网清单（每一条网的处置）

| 网 | 驱动 | fo | 处置 |
|---|---|---|---|
| popPtr | FF | ~8 | 只驱动 robState 4 bank 读地址 + RAM 读地址 |
| 唤醒广播 tag | FF | ~80 | MAX_FANOUT=64 复制 2 份 |
| 捕获式唤醒 data | FF | ~48×32b | 按 IQ 分组复制 4 份 |
| 提交邮箱 | FF | ~8 模块 | 每消费者取字段寄存副本 |
| regFlush/重定向 | FF | ~12 | 按消费者复制 FF |
| 复位 | BUFG+FF | ≤512/网 | 分模块同步复位（§5.3） |
| RAM/CAM 地址(BTB/PRF/ROB/TLB/ICache/DCache) | FF | — | 一律 FF 驱动（已大部分落实） |

### 5.3 复位网络（现状 -2.708ns 单独违例项）

`u_rst_cpu → LUT1 → mem_rstb(fo=6956)` 拆为：顶层同步化 FF（BUFG 驱动）+ 每模块
独立同步复位 FF（fo≤512），消除 2983 个 recovery 违例端点。异步复位仅保留在
绝对必要处（BRAM 原语），且由 FF 驱动。

## 6. 诚实清单：什么必须保持集中（以及为什么无害）

| 结构 | 为什么不能分布式 | 为什么不违反"无中心环" |
|---|---|---|
| PRF(63×32) | 每周期多口读写的统一命名空间 | 3 级读树、写口按地址译码(2 级)，地址 FF 驱动；无决策环 |
| TLB(16 项 CAM) | 每项比较本就逐项本地，命中 mux 4 级 | 输入 VPPN 来自寄存器(快照已做)，输出寄存 |
| ROB RAM + robState | 提交必须按序，头 2~3 项是唯一决策输入 | 决策 5 级局部函数；payload 邮箱寄存 |
| I$/D$/BTB/PHT | 存储阵列，BRAM 输出已寄存 | 前后各 1 拍寄存器，无环 |
| 空闲表/存储缓冲 | 移位队列 = 离散结构的现成例子 | 头/尾指针本地算术 |

**判据**：集中**存储**（RAM/CAM）可以，因为它们的输入输出都被寄存器界定；
禁止的是集中**决策**（一个信号同拍读全局状态并写回）。本设计里唯一的"全局决策"
= 最老 2~3 项的 popCount，输入全为寄存器、输出到指针/邮箱，环已被邮箱寄存器切开。

## 8. 实施路径（每步 regen + 58/58 + perf 构建，沿用现有 CI 环）

- **阶段 1（1~2 天，消 -3.8ns 大头，几乎零 IPC 代价）**：提交链 CM1/CM2（删
  fwdCands + 邮箱寄存 + popPtr 只驱动读地址 + §4.1 的 flush/pop 对齐协议）；
  重定向消息链；复位网拆分。预期 WNS 回升 1.5~2.5ns（乐观估计，以报告为准）。
- **阶段 2（1~2 天）**：`SystolicIssueQueue` 树选版替换 CompressedQueue（唤醒单写者
  位面；tag 总线按 §4.2 豁免先保持组合、data 总线寄存）；译码 3 拍化；**EXE 提前
  重定向（标配，§4.3）**；DISPATCH 瘦身；difftest/调试接口对齐邮箱时序。预期再
  -0.5~1ns，58/58 全绿。
- **阶段 3（性能调优，每项单独一轮 + IPC 实测）**：① **容量扩张**（ROB 32→48、
  INT IQ 7→10——bank/胞元结构下深度几乎零时序代价，用于买回延迟型 IPC 损失）；
  ② 读进胞元双总线（§4.6 #1）；③ 写引擎广播合并（§4.5 C）；④ INT 队列功能分体
  （§4.6 #3）；⑤ retireWidth 3 回补。每项用 `report_design_analysis
  -logic_level_distribution` 验证 ≤10 级、`report_high_fanout_nets` 验证 fo 预算。
- **阶段 4（收尾，随阶段 1/2 数据提前触发）**：axiBuffer FSM 输出寄存（round-4
  候选 #3，核心修完后外设 11~12 级路径会浮出水面，uncached 延迟敏感需 func 仿真
  确认）；pblock/floorplan（IQ/ROB/提交/PRF/前端分块，寄存器边界使 pblock 天然
  可行——级数达标 ≠ 布线收敛，布线占 75%）。

## 9. 风险与验证

1. **每个环必须真的切开**：elaborate 后 grep 网表检查每条环边（唤醒广播→ready、
   robState→popCount→payload、检测→flush→PC）两侧是否各有一级寄存器；组合环
   回归用 xsim 58/58 全覆盖。
2. **乒乓/捕获式的握手指令语义**：rReady 单调置位、发射即清除，双 bank 交换边界
   不许丢唤醒——骨架代码已按"写 B 读 A、下一拍交换"实现；**需补 SpinalSim 参考
   模型比对单测**（随机 enqueue/wakeup/issue 序列 vs 行为模型，覆盖唤醒-发射竞态
   与乒乓边界），Phase 2 集成前完成。
3. **flush/pop 对齐协议（正确性最高风险）**：§4.1 所述 needFlush 晚 popCount
   1 拍与 freeList recover 技巧的交互，Phase 1 必须专项单测（构造"空 ROB 派发+
   立即误预测"、"连续误预测"用例）。
4. **uncached FSM 与邮箱握手**：stateBoot 判定改读邮箱前拍值后，func 套件的
   uncached/MMIO 用例 + Linux 启动（chiplab FPGA 流程）作为回归。
5. **difftest/调试接口**：Dretire*/debug_fifoIO 对齐邮箱时序；difftest 对拍不敏感
   但信号语义必须逐位保持（58/58 中的 difftest 用例覆盖）。
6. **IPC 实测纪律**：每阶段跑 CoreMark/dhrystone perf 计数；同频口径损失 >10%
   即触发补偿（容量扩张/组合 tag 豁免/提前重定向），损失 >15% 停止扩大离散化。
7. **布线收敛余量**：级数达标 ≠ WNS≥0（布线占 75%）。每轮 perf 构建后仍以
   `route_design -directive Explore` + top100 路径报告为准，违例即按 §5.2 找网；
   阶段 4 的 pblock 是收敛的最终手段。
8. **控制集/拥塞**：新增 FF 大量带局部使能（enqueue/wakeup/flush），控制集上升
   会推高布线拥塞（宝典原话）——使能编码尽量复用、复位走同步网络（§5.3）。
