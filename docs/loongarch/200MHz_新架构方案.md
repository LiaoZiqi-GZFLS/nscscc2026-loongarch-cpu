# 200MHz 新架构方案：打散为多拍小片、最小 OoO 核、分散调度

## 0. 为什么逐点压缩无效（用实测数据说话）

| 轮次 | 内容 | 布线 WNS |
|---|---|---|
| r1 | P1 中央分体 robState | -3.842 |
| r2 | P2-P7 提交环压缩/树形读 | -4.095 |
| r3 | P8+P12 前递折叠+译码 MuxOH | **-4.782(回退)** |
| r4 | pop 负载寄存+epilogue 折叠+使能复制 | -3.598 |
| r6 | (构建中)两拍译码+占用计数器 | ? |

原因不在"逻辑级数没压够"，而在三个结构性事实：

1. **布线占 72~84%**：round-3 top1 逻辑 2.72ns/布线 6.99ns；round-4 top1 逻辑
   1.32ns/布线 7.12ns。逻辑再压 1 级只省 ~0.1ns，布线不收敛就永远差 3ns 级。
2. **违例是"锥"不是"路径"**：round-3 有 1091 条 11 级路径（worst-2000 分布），
   round-4 的 33/60 条来自 ROB popPtr 一个寄存器。压缩单条路径只把 WNS 挪走。
3. **跨模块组合链**：round-4 top1 是 commit(except)→regFlush→ICache refetch→
   IF1 stall→regPC.CE，一条链横跨 die(X45→X129)，中间网 fo=80/83。
   局部优化打不断这种链。

结论：**必须把每个大块的边界全部改成寄存器接口，让每一拍 ≤7 级、每张高扇出网
由 FF 驱动，只保留乱序最核心的两条同拍环路**。这就是用户方向（打散小片多拍+
最小调度+分散调度）。

## 1. 预算

- Artix-7 -2 @5.0ns，布线占 70-80% 时：**逻辑 ≤6-7 级/拍，峰值 ≤9**。
- 规则：所有模块间接口 = 寄存器；所有 RAM/多路选择地址 = FF 驱动；跨模块
  fanout > 64 的网 = FF 驱动或显式复制。

## 2. 新架构切片图

```
取指:  IF1(PC+BTB地址寄存) → IF2(BTB/PHT/RAS读+命中) → IF3(目标选择+redirect)
        └─ 预测流水化:下一拍预测在本拍算好(预测寄存器),不用 PC 组合追
译码:  ID1(缓冲pop+65路匹配) → ID2(字段mux) → ID3(epilogue/异常/重命名准备)   ← 已做2拍,允许3拍
重命名: RN1(空闲列表读前推+映射读) → RN2(映射写+ROB/IQ 写口装配)
发射(每队列独立):  IQ1(唤醒比较:EXE广播tag vs 源) → IQ2(优先级选择+读口地址)   ← 2拍发射
执行:  INT ISS/RRD/EXE/WB ; MEM ISS/RRD/ADDR/MEM1/MEM2/WB/WB2(已切片)
提交:  CM1(决策环:读前推状态→ready→fire→popCount,最小环) → CM2(退役动作拍:
       ARF/PRF/BTB/TLB/CSR/freeList 全部用寄存的 payload+fire,晚一拍执行)
```

**只保留两条同拍环**（乱序最核心调度）：
- 唤醒环：EXE WB(寄存器) → tag 广播 → IQ 源比较（1 级）+ 就绪位 → 下一拍选择。
- 提交环：状态读前推(寄存器) → complete/except/mispredict(3bit) → ready → fire。

## 3. 各块切片细节（按杠杆排序）

### A. 提交退役动作整体寄存一拍（最大杠杆）
现状：fire 当拍做 ARF 写/PRF 释放/BTB 更新/TLB 写/CSR/空闲列表，payload(90bit)
从 ROB 状态寄存器扇出到 5 个模块（round-3 freeList/TLB 路径、round-4 残余）。
改法：CM1 决策(ready/fire/popCount)不动；**payload 和 fire 再寄存一拍**，CM2 用
寄存副本做全部动作。重定向(needFlush→flush)同样晚一拍——误预测多跑 1 拍错误
路径，代价 <1% IPC。好处：90bit 状态的大扇出锥整个从关键域消失。

### B. 发射 2 拍化（分散调度）
现状：IQ 唤醒比较(源 tag vs 广播)+年龄/优先级选择+读口地址 一拍完成
（round-3/4 的 IQ rRegs valid 类路径）。
改法：IQ1 = 每队列独立做 tag 比较(4 队列各自 ~16 项 6bit 比较,1-2 级)→就绪位
寄存器；IQ2 = 优先级/年龄选择(2-3 级)→读口+发射。发射延迟 +1 拍(back-to-back
依赖链每跳多 1 拍,IPC 影响 ~3-5%,频率换 IPC 是划算的)。

### C. 前端预测流水化
现状：IF1 的 PC 寄存器 → BTB 读 → 目标 mux → 预测寄存器（round-4 的 14 条
regPC 路径、12 条 PREDICT_JUMP_target 终点）。
改法：预测地址用"下一拍 PC"提前一拍发出(预测寄存器驱动下一拍读),BTB/PHT 读
结果在 IF2 寄存器化,IF3 只做选择与 redirect;redirect 用寄存的 fire 副本(与 A 合流)。

### D. 译码允许 3 拍（已做 2 拍,round-6 在建）
若 round-6 数据仍显示 ID2/RENAME 深:把 epilogue 里的 CSR/Timer/异常汇总裁剪
到 ID3。当前 2 拍每拍 ~7 级,理论上够了,留作保险。

### E. MEM 地址链
RRD 算低 16 位+进位(4 CARRY4),MEMADDR 算高 16 位(4 CARRY4)+TLB 阶段 1;
TLB 比较本身再拆:VPPN 比较(MEMADDR)→命中 mux(MEM1)。若 MEM1 深,TLB
快照从 16 项 3 级树读改为 2 拍(比较/选择分拍)。

### F. retireWidth 3→2
一行开关(MyCPUConfig.scala)。提交侧所有扇出/环宽再降 1/3,空闲列表/ARF 端口
减半。IPC 代价与 B 同源,可接受。

### G. 高扇出网清单(全部 FF 驱动或复制)
ROB popPtr(round-4 33 条)、RAM 读地址(ICache/DCache/BTB/PRF/ROB RAM)、
级间采样使能(fo≈1000,round-4 已加 max_fanout)、commit fire 广播。

## 4. 实施顺序（每步 regen+58/58+构建，数据驱动）

1. round-6 构建结果(两拍译码+占用计数器) → 决定 A/B/E 顺序。
2. **A(提交动作寄存)** — 最大杠杆,~半天。
3. **B(2 拍发射)** — 次杠杆,~半天。
4. C/F/G 按 round-7 数据补。
5. 预期:每步 -0.8~-1.5ns,2~3 步后 WNS≥0。

## 5. 风险与边界

- 每次架构改动必须 58/58 门(已有自动化);误预测延迟+1 拍、发射延迟+1 拍、
  提交动作晚 1 拍都是"正确性由恢复机制兜底、性能代价 <5%"的标准做法。
- 不新增乱序资源(ROB 32/IQ 容量不变),面积基本持平。
- 若 A+B+F 落地后仍差 <0.5ns,再用 phys_opt 定向复制收尾;若 >1ns,说明还有
  未发现的长链,按布线报告再切。
